# Manafish Python SDK v1

A custom action is one UTF-8 `.py` file that declares one module-level `Script`
from `manafish_sdk`. The readings and functions registered on it become the
app's catalogue. `manafish_sdk` exports `Context`, `Script`, `Reading`,
`Trigger`, `Widget`, `NotificationLevel`, and `RovState`.

```python
from manafish_sdk import Context, Script, Trigger, Widget

script = Script("depth_monitor", name="Depth monitor")
depth = script.reading("depth", float, unit="m", widget=Widget.TEXT)

@script.action(name="Read depth", modes=(Trigger.ONCE, Trigger.HOLD))
async def read_depth(ctx: Context) -> None:
    if not ctx.rov.system_health.pressure_sensor_healthy:
        await depth.publish(None)
        raise RuntimeError("Pressure sensor is unavailable")
    await depth.publish(ctx.rov.pressure.depth)
```

The installed Water sensor, Blackbox logging, and Extended telemetry scripts are
complete examples. Open them with **Edit script**.

## Source code

Manafish is open source on GitHub. When this guide does not answer a question,
read the source there instead of guessing:

- Firmware: https://github.com/manafishrov/firmware. It contains the
  `manafish_sdk` package (`src/manafish_sdk/`), the custom-action runtime
  (`src/rov_firmware/custom_actions/`), the installed example scripts
  (`src/rov_firmware/custom_actions/defaults/`; `examples/custom_actions/` in
  v1.2.0-rc.3 and earlier), and `RovState` (`src/rov_firmware/rov_state.py`).
- App: https://github.com/manafishrov/app
- All repositories: https://github.com/manafishrov

The `main` branch can be newer than the firmware on this ROV. Release tags, for
example `v1.2.0`, match firmware versions.

## IDs

The script ID uses lowercase letters, digits, and underscores, starts with a
letter, and has at most 48 characters. `rov` is reserved. Reading IDs and
function names become `script_id.name`. Keep IDs stable so widgets and bindings
survive updates; `@script.action(identifier="old_name")` keeps an ID when a
function is renamed.

## Readings

`script.reading(id, type, name=..., unit=..., widget=..., stale_after=...)`
accepts `bool`, `int`, `float`, `str`, `list[float]`, or a NumPy array type.
`await reading.publish(value)` must match that type; numbers must be finite and
arrays have at most 4096 items. Publish `None` when a value is unavailable.

Widget suggestions are `Widget.TEXT`, `STATUS`, `WARNING`, `PING`, and `BAR`.
Operators add and place widgets in Appearance. For continuous readings, set
`stale_after` in seconds and publish every sample; the widget shows **Stale**
when no value arrives in time.

## ROV state

`ctx.rov` is the live firmware `RovState`, with its original Python and NumPy
types, for example `ctx.rov.pressure.depth`, `ctx.rov.regulator.roll`,
`ctx.rov.imu.acceleration`, and `ctx.rov.system_status.depth_hold`. Controls
include `await ctx.rov.set_desired_depth(12.0)` and
`await ctx.rov.set_desired_attitude((0.0, 0.0, 0.0, 1.0))` (XYZW). Check
`ctx.rov.system_health` before trusting sensor values. Definitions live in
`rov_firmware/rov_state.py` and `rov_firmware/models/`.

## Actions and background work

`@script.action()` registers `async def name(ctx: Context)`. Triggers are
`Trigger.ONCE` (default), `HOLD` (repeat while held), and `TOGGLE` (repeat until
pressed again). List the allowed triggers in `modes`, and set the initial `mode`
and `interval_ms` (default 250, range 50–3600000). Operators change these in
Custom actions and bind actions in Keyboard, Controller, and Appearance. Do one
operation per call: the firmware repeats it without overlap and stops operator
actions on disconnect. A typed second argument, such as `value: float`, creates
an API action that is not offered as a button binding.

`@script.background()` registers one `async def name(ctx: Context)` that runs
while the script is enabled and an app is connected. With
`continue_on_disconnect=True`, it also runs without an operator and starts after
a ROV restart. Loop with `await asyncio.sleep(seconds)`, and keep actuator
control in explicitly invoked actions.

## Hardware and libraries

The ROV is a Raspberry Pi 3 Model B+ (4 cores, 1 GB RAM). Scripts run as the
`pi` user without root, so use the interfaces below. GPIO is 3.3 V and not 5 V
tolerant. Pins are BCM GPIO numbers.

- GPIO: `gpiozero` (lgpio backend) for inputs, outputs, buttons, and relays.
  Its PWM is software-timed and jitters; use hardware PWM for servos.
- I2C: `/dev/i2c-1` (GPIO2 SDA, GPIO3 SCL) with `smbus2`. The bus runs at 1 MHz
  and is shared with the ROV's pressure sensor (0x76) and IMU (0x68), so a device
  must support 1 MHz and use another address.
- SPI: `/dev/spidev0.0` (CE0 GPIO8) and `/dev/spidev0.1` (CE1 GPIO7); MOSI GPIO10,
  MISO GPIO9, SCLK GPIO11. Use `spidev`.
- Addressable LED strips (WS2812/NeoPixel): connect Din to GPIO10 and send SPI
  at 2.4 MHz with three SPI bits per LED bit (`0` -> `100`, `1` -> `110`), GRB
  byte order, followed by at least 300 µs of zero bytes. `rpi_ws281x` and
  `neopixel` are not installed and would need root.
- Hardware PWM: GPIO18 is `/sys/class/pwm/pwmchip0` channel 0, GPIO19 is channel 1.
  Write the channel to `export`, then `period` and `duty_cycle` in nanoseconds
  and `1` to `enable` under `pwm0/` or `pwm1/`. udev grants access shortly after
  export, so retry briefly. Disable and `unexport` in cleanup. Servos use a
  20 ms period and 1-2 ms pulses.
- 1-Wire: GPIO4 with an external 4.7 kΩ pull-up to 3.3 V. DS18B20 probes appear as
  `/sys/bus/w1/devices/28-*/temperature` (millidegrees Celsius). Each read takes
  about 750 ms; use `asyncio.to_thread`.
- Serial: USB-serial adapters appear as `/dev/ttyUSB*` or `/dev/ttyACM*`. Use
  `serial_asyncio_fast` or `pyserial`. The ROV's own Raspberry Pi Pico
  microcontroller is also a `/dev/ttyACM*` device: select your adapter by USB
  VID/PID or serial number with `serial.tools.list_ports`, never by index. The
  GPIO14/15 UART is the system console and is not available.

Installed libraries: the Python standard library, `numpy`, `scipy`, `pydantic`,
`gpiozero`, `lgpio`, `smbus2`, `spidev`, `pyserial`, `serial_asyncio_fast`,
`pynmea2` (GPS NMEA sentences), `pymodbus` (Modbus RTU/TCP for RS-485
instruments), `psutil`, `websockets`, `ms5837`, and `bmi270`.

Not available: root, `/dev/mem`, DMA, the camera (the video stream owns it),
internet access, and installing packages. Firmware v1.2.0-rc.3 and earlier
lacks SPI, hardware PWM, 1-Wire, serial adapter access, `spidev`, `pynmea2`, and
`pymodbus`. When a device or library is missing, raise an error that names it.

## Rules

- Module initialization only declares configuration, readings, and functions.
  Open hardware, write files, and start work inside registered functions.
  Validation imports the module but never runs actions or background work.
- Scripts are trusted Python in the firmware process, limited to 256 KiB. New
  scripts are installed disabled.
- Module variables hold state, preferably in a Pydantic model. State resets when
  the script reloads, is disabled, restarts after a disconnect, or the ROV
  restarts. Use a lock when an action and the background share state or hardware.
- Never block the event loop. Use `asyncio.to_thread` for blocking I/O and await
  it during cleanup. Release resources in `try/finally`, let
  `asyncio.CancelledError` propagate, and avoid detached tasks or threads.
- Installed libraries can be imported; installing others is not supported.

## CSV, notifications, and logs

`await ctx.log_csv([value1, value2], "readings.csv")` appends one row from a list
or one-dimensional NumPy array. Use a plain `.csv` filename, keep the column
count constant, and write a header only once. Recordings are listed in CSV
logging; files are limited to 64 MiB each and 256 MiB in total.

For rolling logs, `delete_oldest="my_log_"` permanently deletes other CSV files
with that filename prefix in filename order when needed to fit a row within the
total limit. Use a prefix reserved for your script, and rotate files at the
per-file limit. `await ctx.csv_filenames()` lists stored filenames without
reading their contents. Blackbox logging uses a zero-padded sequence continued
from disk, so a wrong Pi clock cannot change which recording is deleted first.

`await ctx.notify("Water detected", level=NotificationLevel.WARNING)` shows a
notification. Levels are `INFO` (default), `SUCCESS`, `WARNING`, and `ERROR`;
`description` adds plain text, and `key="status"` replaces the script's previous
notification with that key. Notify on changes, not on every sample.

`await ctx.log("message")` writes to the Debug page. An unhandled error stops the
script and shows its message. Report missing hardware as an error; never publish
simulated values.

## Editor

The editor type-checks drafts locally against the connected ROV's SDK
definitions, cached for offline use, without running them. Static checks cannot
prove that hardware exists or that an operation is safe.

## Installing

A custom action needs a single Python `.py` file. Open it with **Import script**
on the app's Custom actions page, then select **Save** while connected to the
ROV to install it.
